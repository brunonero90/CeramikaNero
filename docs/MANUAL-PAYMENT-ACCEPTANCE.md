# Manual payment acceptance (studio owner)

Use this checklist after deploying payment/booking changes. You do **not** need database access.

**Rules**

- Use **Stripe test mode** only (`pk_test_` / `sk_test_`). Never use live keys.
- Create a **new CN-O cart order** for each row (do not reuse a paid order).
- Cards: any future expiry (e.g. `12/34`), any 3-digit CVC, any postal code.
- Official Stripe card reference: [docs.stripe.com/testing](https://docs.stripe.com/testing)
- Official BLIK sandbox failures: [BLIK Checkout testing](https://docs.stripe.com/payments/blik/accept-a-payment?payment-ui=checkout#test-blik)

**Polish UI labels you will see**

| Place                  | Label                                                            |
| ---------------------- | ---------------------------------------------------------------- |
| Pay button             | **Zapłać online**                                                |
| Bank transfer          | **Przelew bankowy** / transfer instructions on `/zamowienie/...` |
| Order awaiting payment | **Czeka na płatność** (or similar unpaid state)                  |
| Paid order             | Payment button gone; status shows paid/confirmed                 |
| Admin orders           | `/admin/zamowienia` → open the order by reference                |
| Admin mark paid        | Operational payment status → **paid** (bank transfer only)       |

**Evidence to save for each PASS**

1. Screenshot of Stripe Checkout result
2. Screenshot of `/zamowienie/[token]` after return
3. Screenshot of admin order page
4. Email subject/inbox (no need to forward full body with address if you prefer)
5. Optional for tech: Stripe Dashboard → Developers → Events → HTTP status for the webhook

## What “good” looks like (simple)

- Green Stripe + unpaid site for more than ~1–2 minutes → **fail** (note order reference; ask tech to check webhook + return reconcile).
- Declined Stripe + site shows paid → **fail** (stop; do not take more test payments).
- Paid twice for one order → **fail**.
- After refund, seats do not automatically free — that is expected; cancel the booking in admin if the person will not attend.

## Optional technical evidence

- Stripe Dashboard → Developers → Webhooks → recent deliveries (status code).
- Admin → order events / payment status.
- Do **not** paste secret keys, full customer emails in shared chats, or live Dashboard screenshots with real customers.
